The idea

You're about to ask Claude to generate an entire website's worth of files. This works — reliably — but only with the right setup, because a vague request produces a generic site with invented content, and a specific request produced from your Canon File produces your site.

Two rules for this module:

Work inside a Claude Project. Your Canon File and pillar map live in project knowledge. Every conversation in that project loads them automatically. Building outside the project means re-explaining your business every time and getting drift every time.

One task per conversation. Not one conversation for the whole build. Long conversations lose the thread — earlier instructions get outweighed by later ones, and you'll get a second version of a page you already have. Scaffold in one chat, layouts in another, articles one per chat.

Do this — the scaffold prompt

New conversation in your project. Paste this, filled in:

Build the scaffold for my Astro site. Use my Canon File in project
knowledge as the source of truth for everything.

LIVE FACTS — these override anything that disagrees:
- Domain: [yourdomain.com or learn.yourdomain.com]
- URL pattern: /learn/[slug] — flat, no category folders
- Deploying to Vercel from GitHub
- Colors and fonts: as specified in the Canon File

What I need:
1. package.json with Astro and the Vercel adapter
2. astro.config.mjs configured for Vercel, with my site URL set
3. A base layout at src/layouts/PageLayout.astro — nav, footer,
   fonts loaded, brand colors as CSS variables
4. A homepage at src/pages/index.astro
5. A /learn index page that lists articles AUTOMATICALLY using
   Astro's glob import over src/pages/learn/ — reading each
   article's title, description and category from its frontmatter.
   I don't want to hand-maintain a list.
6. tsconfig.json, .gitignore, robots.txt

Rules:
- Do not invent products, prices, links, or copy. If you need a fact
  that isn't in my Canon File, stop and ask.
- Placeholder text is fine where real copy comes later — mark it
  clearly as PLACEHOLDER.
- Give me each file complete, with its exact file path. No fragments.

Claude returns a set of complete files. Read them for invented products — that's the one thing to check. If a price or product appears that isn't in your Canon File, say That product doesn't exist. Remove it. and it will.

Do this — the homepage

The scaffold gives you a homepage with PLACEHOLDER text. Fill it now, or you'll finish the weekend with a live site whose front page says PLACEHOLDER.

It needs four things and nothing else:

Write the homepage copy for src/pages/index.astro. Use my Canon
File and pillar map in project knowledge.

Four sections only:
1. A headline saying who I help and what they get — no tagline
   fluff, a plain sentence a stranger understands
2. A short paragraph on what this site is for
3. The pillar topics as links to /learn — use my actual pillars
4. One email signup link to [your opt-in URL or PLACEHOLDER
   for now — Module 12 fills it]

Rules:
- No invented products, prices, testimonials, or credentials
- No "welcome to my blog"
- Complete file, ready to paste

Nothing else belongs on a homepage on day one. You can add to it once you have traffic telling you what people want.

Do this — getting files into GitHub

Two routes. Pick one and stay with it.

Route A — the web interface. Slower, zero setup, works on any computer. In your repo: Add file → Create new file. Type the full path in the filename box (src/layouts/PageLayout.astro — the slashes create the folders automatically). Paste the contents. Scroll down, Commit new file. Repeat per file.

Roughly 8 files for the scaffold. Fifteen minutes.

Route B — Claude commits for you. Faster, more setup. You create a GitHub personal access token and Claude pushes files directly through GitHub's API. Covered fully in Module 19, along with the security practices that make it safe.

Do Route A this morning. It gets you live today with nothing to configure. Switch to Route B once you're publishing weekly and the clicking gets old.

Roadblock — "Claude gave me a fragment, not the whole file"

Say: Give me the complete file, top to bottom, ready to paste. No omissions, no "rest of file unchanged." Partial files are the single most common cause of a broken build, because you paste it, something's missing, and the error message points somewhere unrelated.

Roadblock — "I don't know if this file is right"

You don't need to. If it's wrong, the deploy fails with an error message. Paste the error back to Claude and it fixes it. That loop — deploy, error, paste, fix — is a normal part of the build, not a sign you're doing it wrong.

Roadblock — "Claude wrote copy about my business that's wrong"

Your Canon File has a gap. Add the correct fact to the Canon File, re-upload it to project knowledge, and regenerate. Fixing the output alone means the same error comes back next time.
