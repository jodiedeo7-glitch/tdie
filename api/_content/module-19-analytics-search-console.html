Two tools, different jobs. You need both and neither takes long.

Search Console tells you what happened in Google — what people searched, what you appeared for, what got clicked. It's the only place this data exists.

Site analytics tells you what happened on your site — which pages people read, where they came from, where they left.

01

Analytics

If you're on Vercel, use Vercel Analytics. It's built in, it's free at your level, and it needs no cookie banner because it doesn't track individuals.

Copy this prompt
Add Vercel Web Analytics to my site. Add the package to
package.json and include the Analytics component in every layout
that renders its own <html> tag — check all of them, not just
the main one. Give me each changed file complete.

The trap: if any page has its own <html> instead of using a layout, analytics won't load there and that page reports zero traffic forever. Ask for every file, not the obvious one.

Then enable it in the Vercel dashboard — Project → Analytics → Enable. Code alone isn't enough.

02

Search Console

Set up in Module 7. Now use it. Two reports:

Performance — every search that showed your site, with impressions, clicks, and position. This is where your next articles come from.

Pages — what's indexed and what isn't, with reasons.

03

The pixel, if you run ads

Skip this if you don't run Meta ads. If you do, it is the thing most likely to be quietly broken right now.

Your funnel crosses two domains. The sales page sits on the domain you built this weekend. The checkout sits somewhere else — Beacons, Stan, Gumroad, Podia. That host installs a pixel for you the moment you paste an ID into its settings, so Meta sees the purchase and never sees the page in front of it.

Which means you can run ads for months, watch purchases land, and still have no retargeting audience. The audience worth having is the woman who read the entire sales page and didn't buy. If the pixel isn't on your own domain, she doesn't exist as far as Meta is concerned.

One ID in both places. Don't create a second pixel for the new site because the existing one is named after an older brand. Two IDs split the learning in half and neither half gets good.

Copy this prompt
Add the Meta Pixel base code to my Astro site. My pixel ID is
PASTE_YOUR_ID. Put it in the head of every layout file that renders
its own <html> tag — check all of them, not just the main one.
Use <script is:inline> so Astro ships the snippet exactly as
written instead of bundling it. Include the noscript fallback.
Give me each changed file complete.

The trap: Astro bundles and defers a plain script tag, which lifts your pixel out of the head and changes when it fires. is:inline tells it to leave the snippet alone. Same shape as the analytics trap above — every layout with its own <html> tag, not just the obvious one.

The second trap: if your checkout host already sends Initiate checkout and Purchase, don't add your own click handler to the handoff link. You'll count every checkout twice and then optimise against numbers that aren't real.

Confirm it worked in Events Manager: open the dataset and read the Websites list in the right column. Your domain should appear there within about half an hour, sitting alongside the checkout host.

What actually matters in month one

Impressions. Not clicks — impressions. Impressions mean Google is showing you. Clicks follow, but impressions move first and they're the early signal that anything is working.

Which queries you appear for. Frequently not the ones you targeted. This is genuinely useful information: a query you're at position 15 for, that you never wrote about deliberately, is an article you should write on purpose.

Which pages get indexed. New pages take days to weeks. If something isn't indexed after a month, check it for a noindex tag or an orphaned URL with no internal links.

What does not matter in month one

Traffic totals, bounce rate, time on page, and every number a course sells you a dashboard for. Your sample size is too small for any of it to mean anything, and watching them daily is how people talk themselves into quitting a system that's working normally.

Check monthly. Not daily.

If you get stuck
Analytics shows zero

Enabled in the dashboard? Snippet in every layout? Ad blocker on your own browser? Check in that order.

Search Console shows nothing after two weeks

Normal. New sites take weeks to accumulate enough data to display. Nothing to fix.

Pixel fires on the page but Meta shows no audience

Audiences build forward from the day you install. There is no backfill, and nothing you sent before today counts. Give it a few hundred people before you judge it. Then check your root domain is verified in Business Settings — verification happens on the root domain, and one record covers every subdomain underneath it.

Before you move on

Analytics on every layout and enabled in the dashboard, Search Console verified with a submitted sitemap. If you run ads: one pixel ID on both halves of the funnel, and your root domain verified.
