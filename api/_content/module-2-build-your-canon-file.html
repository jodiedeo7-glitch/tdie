Read this part twice

Most important module in the course, and the one people skip. Skip it and everything downstream breaks quietly.

Here's what happens without a Canon File. You ask Claude to write about your membership. It writes a beautiful article mentioning your "Starter Tier at $19/month." You don't have one. You've never had one. It sounded plausible, so it appeared. You publish because it reads well. Three weeks later someone emails asking to buy it.

That's not Claude broken. That's Claude filling a gap to complete a pattern. The fix is to leave no gaps.

A Canon File states what exists, what it costs, where it lives, how you talk, and what's forbidden. Load it into your project and Claude stops inventing, because it no longer has to guess.

What goes in it

Products — exact. Every product, exact price, exact full name, exact live URL. No URL yet? Write PENDING — do not invent.

Hard rules. What must never happen. Blunt and specific.

Voice. Three descriptors and a banned word list. The banned list does more work than any description — "never say hack, secret, explode, crush it, game-changer" changes output more than a paragraph about your vibe.

Structural facts. URL pattern, stack, colors, fonts.

What does NOT exist. The line most people leave out, and the one that prevents the most damage.

Copy and fill

Copy this prompt
CANON FILE — [YOUR BRAND]

PRODUCTS — exact names, exact prices, exact URLs
| Product | Price | Platform | URL |
|---|---|---|---|
| [Full™ Name] | $X | [platform] | [url or PENDING] |

DOES NOT EXIST — never reference these
- No free trial
- No annual plan
- No 1:1 coaching
- [every plausible thing you don't offer]

HARD RULES
1. Never invent a product, price, link, or CTA. Not in the table above = does not exist.
2. If something is missing, stop and ask. Do not fill the gap.
3. Full trademark name on first reference.
4. When two sources conflict, stop and flag it. Never resolve it silently.

VOICE
Sounds like: [three descriptors]
Never say: hack, secret, explode, crush it, game-changer, [your additions]
Register: [e.g. warm and direct in community, editorial on the blog]

STRUCTURE
URLs: /[pattern]/[slug]
Stack: [your stack]
Colors: [hex codes]
Fonts: [names]

The second half of Module 2

A wrong Canon File is worse than none, because Claude trusts it completely.

The filename lies. You save resource-map.md. Six weeks later you paste it in and it's actually an old decisions log you renamed. Claude builds on it. Everything downstream is wrong and looks fine.

Fix: start every canon file with a title and version line — # RESOURCE MAP v2.1 — updated Aug 3 — and read the first three lines before using it. Four seconds, saves a rebuild.

The document goes stale. Your file says 3 articles are live. There are 11. Claude plans around 3 and builds a linking structure that ignores 8 pages.

Fix — the live-facts block. Don't rewrite the file. Paste an override at the top of your request:

Copy this prompt
LIVE FACTS — these override anything in the Canon File that disagrees.
Project knowledge is stale on these points:
- [fact]
- [fact]
- [fact]
Where the Canon File and this block conflict, this block wins.

That's what keeps one Canon File useful for months instead of decaying in a week.

The rule that makes this work

Save this as a standing instruction:

When my instructions conflict with the canon, or two documents disagree, STOP and flag it. Do not resolve it silently.

Silent resolution is the expensive failure — you get a finished, confident, wrong deliverable and no signal anything happened. A stop costs thirty seconds.

If you get stuck
Claude keeps forgetting my Canon File

Don't paste it per-message. Put it in a Claude Project as project knowledge or project instructions, and it loads on every conversation automatically. This course assumes you're working inside one project.

I updated the file but Claude uses the old version

Uploaded files don't sync from your computer. Delete the old one and re-upload. Same filename ≠ same file.

Before you move on

A Canon File in your project knowledge, plus the conflict-flag instruction in your project instructions.
