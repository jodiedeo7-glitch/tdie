TROUBLESHOOTING VAULT

Every problem hit during a real build of this system, paired with the fix that actually worked.

How to use this: find your symptom, apply the fix. Nothing here is theoretical — each one cost someone real time.

1 · SETUP & DEPLOY

"It's asking me to choose a plan." Free tier, on GitHub and Vercel both. Paid tiers are for teams and commercial usage.

"Public or private repo?" Private. Your published site is public regardless; the repo holds drafts and config.

"I already own a domain and it's in use." Use a subdomain — learn.yourdomain.com. Don't move your existing site.

"Vercel says the domain is already in use." It's attached to another service or another Vercel project. Remove it there first, or use a subdomain.

"My domain shows a certificate warning." Almost always DNS still propagating. Vercel issues SSL automatically once DNS resolves. Wait a few hours before touching anything — the most common cause of a real break here is someone "fixing" a warning that was about to clear.

"The deploy failed." Normal. Open Vercel's build log, copy the error, paste it to Claude. Deploy → error → paste → fix is a standard part of the build, not a sign you're doing it wrong.

"It deployed but the site didn't change." Check the deployment log. A build error means Vercel keeps serving the last working version — the system protecting you. Fix the error and it redeploys.

2 · FILES & LAYOUTS

"Claude gave me a fragment, not the whole file." Ask for the complete file explicitly. Partial files are the single most common cause of a broken build — you paste it, something's missing, and the error points somewhere unrelated.

"I don't know if this file is correct." You don't need to. If it's wrong, the deploy fails and tells you. Paste the error back.

"My four standalone pages each have their own header." Common when pages get built before the layout exists. Every one is a separate edit for every future change. Refactor them onto the layout now — the longer you wait, the more they drift apart.

"I have to change the same thing in forty files." That thing belonged in a layout. Move it there, then delete it from the individual pages. Rule: if it appears on more than one page, it lives in the layout.

"A file named one thing turned out to contain something else." This one costs whole rebuilds. You paste in resource-map.md and it's actually an old decisions log you renamed. Claude trusts it completely and everything downstream is wrong while looking fine. Fix: every canon document starts with a title and version line — # RESOURCE MAP v2.1 — updated Aug 3. Read the first three lines before using any file. Four seconds.

"I have two related-article blocks at the bottom of every article." Module 11's journey block was added alongside Module 6's block instead of replacing it. Tell Claude to remove the old one — there should be exactly one block at the end of an article.

"My /learn page is empty even though articles are live." The index isn't reading them automatically. It should glob over src/pages/learn/ and read title, description and category from each article's frontmatter — and each article has to export those. Hand-maintained lists always fall behind.

"My homepage says PLACEHOLDER." The scaffold ships placeholder copy on purpose. Module 5's homepage prompt fills it. Four sections, nothing more.

"My article shows a broken image box." featuredImage points at a file that isn't in the repo. Either commit the image to public/images/ or remove the prop — an article without an image still ranks fine.

"A page has its own <html> tag and analytics doesn't load there." Any page bypassing the layout misses everything the layout provides. Ask Claude to check every file that renders its own <html>, not just the obvious one.

3 · WRITING WITH CLAUDE

"It mentioned a product I don't sell." Your Canon File has a gap. Add it to the DOES NOT EXIST list, re-upload, regenerate. Fixing only the output means it recurs.

"It came out at 1,800 words instead of 3,000." Ask for depth, not length. Naming what you don't want — padding, restatement — matters. Asking only for "longer" gets you restatement.

"It doesn't sound like me." Your voice section is too vague. The banned word list changes output more than any description. Add ten words you'd never say.

"It rewrote my whole article during an SEO pass." Ask for changes only, with exact replacement text. Full rewrites lose good material you didn't ask it to touch.

"Claude keeps forgetting my Canon File." Don't paste it per-message. Put it in a Claude Project as project knowledge and it loads on every conversation automatically.

"I updated a file but Claude uses the old version." Uploaded files don't sync from your computer. Delete the old one, upload the new one. Same filename ≠ same file.

"It keeps asking questions I already answered." The answer is in the conversation but not in project knowledge, so it doesn't survive to the next chat. Anything you answer twice belongs in your Canon File.

"Claude won't build it — it's asking questions instead." That's the system working. A stop means it found something that would have made the output wrong. Answer the question, then fix the cause so it doesn't recur. Don't tell it to guess — you'll get a confident wrong deliverable you can't audit.

"It stopped on something I don't care about." Tell it explicitly to omit that slot and continue. Directing an omission is completely different from telling it to guess.

"I ran one huge prompt and got a mess." Roles cancel each other, context collapses, and overlapping requests produce duplicate structures. Role and context in project instructions once; one task per conversation after that.

4 · LINKS & ROUTING

"My related links point to articles I haven't written." Remove them. A link to a page you plan to write is a broken link today.

"I have forty articles with hardcoded links." Convert as you touch them, not all at once. Next time you edit an article, move its links into props. Done within a month, no dedicated project.

"My canon says one URL and the live site uses another." The live site wins, always. Then fix the document so the conflict doesn't recur.

"Someone clicked my free resource and hit a paywall." Anything in the free slot must be genuinely $0. Not free-with-membership, not a trial. This doesn't just lose the click — it costs you the trust you spent 3,000 words earning.

"A pillar has no matching paid product." Leave it empty. Substituting the nearest product teaches readers your recommendations aren't about them. The gap is also your product roadmap.

"An empty slot rendered as a broken link." Your layout is filling slots rather than omitting them. The rule: if a prop is missing, render nothing. An omitted slot costs one opportunity; a broken link costs trust at the exact moment someone was interested.

5 · EMAIL CAPTURE

"My form was live and broken for months." The most expensive failure in this build. It looks perfect, the button clicks, nothing is captured, and because it's in the layout it's on every page at once. Fix: don't build a form. Link to your email platform's hosted signup page. Their infrastructure, cannot silently break. Then: test it yourself monthly. Sign up with a real email. Ninety seconds.

"Claude generated a form with onsubmit='return false'." That form is decorative. It does nothing. Ask for the link version.

"I don't have an email platform." Pick one tonight, use the free tier. Which one matters far less than starting to collect — the list you don't build this month is the one you don't have next year.

"Someone found my gated PDF without signing up." It's at a public URL. Anything in your site's public folder is public — no exceptions. Move the file to your email platform's delivery and remove it from the site.

6 · SEO & INDEXING

"Search Console says my sitemap couldn't be fetched." Almost always the URL format. Full address with https://, matching your canonical domain exactly including whether you use www. Use a URL-prefix property, not a Domain property — they behave differently here.

"Discovered pages: 0." Normal on day one. Google takes days to weeks on a new site. Nothing is broken.

"Search Console shows nothing after two weeks." Also normal. New sites need weeks to accumulate displayable data.

"My site is reachable at four different addresses." To a search engine those are four sites with identical content. It splits your ranking signal or picks one arbitrarily. Pick one canonical address, 301-redirect the rest to it. Permanent, not temporary — only a 301 passes ranking signal.

"A page isn't getting indexed after a month." Check for a noindex tag, and check that something on your site links to it. An orphaned page with no internal links is hard for Google to find.

"Google needs a publish date and my pages don't have one." Pass a real date on every article. Never invent one — if it's missing, omit it from the schema. You lose a rich result; faking it costs more if caught.

"Analytics shows zero." In order: enabled in the dashboard? Snippet in every layout? Ad blocker on your own browser?

7 · PINTEREST

"My links got flagged as spam." Four causes, fix all of them: 1. Raw affiliate links in pins → route through bridge pages 2. Link-in-bio platform domains → these carry everyone else's reputation 3. Money-shouting page titles → reads as spam to an automated system 4. Multiple domains serving identical content → fix with 301s

Then wait for a re-crawl — one to two weeks — before appealing. Appealing while the flagged pattern is still live gets you denied and burns the appeal.

"I got a certificate warning while diagnosing a Pinterest problem." Frequently a false alarm from DNS mid-propagation, unrelated to the flag. Confirm it's real before acting on it.

"My pins get impressions but no clicks." The title isn't promising a specific enough outcome, or the image doesn't match the promise. Test titles first — faster variable.

"Nothing is happening at all." Pinterest takes 60–90 days to start reading a new account. The most common reason people quit right before it works.

"I have 18 boards and most are empty." Empty boards dilute the account. Merge down to 8–12, fill the ones you keep before creating more.

"Two of my boards target the same terms." Merge them. Two half-boards split your own signal.

8 · IMAGES

"My images look like 3D renders." Add "a real photograph, not a 3D render, not CGI" and real camera specs. Both, not one.

"Three covers look like three different brands." Generated separately, so they drifted. Use a locked shell — one prompt with everything fixed except named swap fields.

"Colors don't match my brand." Hex codes in every prompt, every time. Color names aren't precise enough — "pink" spans a hundred colors.

"My headline color came out pale and too small." Specify saturation and dominance explicitly: "bold saturated [hex] — deep and vivid, not pale — large enough to dominate the panel."

"There's a hard visible seam where the text panel meets the photo." Ask for a soft gradient blend at the transition. Without it you get two pasted rectangles.

"The text panel has a big empty area." Specify that text uses the space generously — no dead area, no floating text island.

"My subject's clothes came out washed out." Add: colors rendered rich and true-to-tone, not desaturated by the light.

"The bottom strip is thin and see-through." Specify substantial height and fully opaque. "Strip" alone gets you a translucent band.

"The headline is misspelled in the generated image." Don't regenerate and hope. Open it in Canva and lay correct text over it. Faster and certain. Always check text before publishing.

"My generated person looks different every time." Stop describing her in words — word descriptions drift. Generate one image, save it as a reference, attach it to every future generation as "this exact person," and describe only what changes.

"My account got restricted over an image." Trademarked characters, brands, or logos in generated images. Hard ban, no exceptions, some platforms don't offer appeals.

9 · PUBLISHING & GITHUB

"It says 404 or not found." Almost always the token lacking access to that specific repo, not a wrong path.

"I pasted my token in chat and it refused to use it." That's the correct response, not a malfunction. Revoke that token and issue a fresh one when you're ready.

"I want to undo a commit." Commit a fix forward instead of reverting. Reverting is where people accidentally erase work, and your old versions are all still in the repo either way.

"I have a lot of files to commit." One commit with all files in a single tree, not one commit per file.

"Committing images fails." Binary files need base64 encoding with the encoding flag set in the blob payload.

"I forgot to revoke a token." Revoke it now. Make it reflexive at the end of every session — a token you forgot about is the one that causes the problem.

10 · KEEPING IT RUNNING

"I fell off for a month." Nothing was lost. Articles kept ranking, pins kept circulating — that's the whole point of assets over feeds. Restart at one article a week. Don't try to catch up; catching up is how people quit twice.

"I can't do 2 hours a day." One hour, three days a week, slower pace. Consistency at a low rate beats bursts, because only one of the two survives a busy month.

"I have twelve pillars and can't keep up." You don't need twelve. Five deep clusters outperform twelve thin ones. Cut the ones you don't want to write about.

"A pillar has three supporting articles a year in." Cut it. That's not a backlog, it's a topic you don't actually want to write about. Put the effort into a pillar that's pulling.

"My affiliate link goes to a dead product." Verify quarterly — products get retired, repriced, and pulled without notice. If everything routes through bridge pages, fixing it is one page edit instead of hunting every pin you ever posted.

"I check my analytics constantly and get discouraged." Monthly, not daily. Your sample size is too small for daily numbers to mean anything, and watching them is how people talk themselves into quitting a system that's working normally.

"Which numbers actually matter early?" Impressions, which queries you appear for, and which pages get indexed. Not traffic totals, bounce rate, or time on page — not yet.
