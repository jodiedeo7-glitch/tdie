The idea

You've been pasting files into GitHub's web interface. It works and it's fine. Once you're publishing weekly it gets old — a single article with images can be six or seven separate paste-and-commit cycles.

The upgrade: Claude commits directly to your repo. You approve, it pushes, Vercel deploys. One step.

This module is optional. Skip it if the clicking doesn't bother you.

Do this — create a token

A personal access token is a password that grants access to your repositories.

GitHub → Settings → Developer settings → Personal access tokens → Fine-grained tokens → Generate new token.

  • Repository access: only the one repo. Never "all repositories."
  • Permissions: Contents → Read and write. That's all it needs.
  • Expiration: 30 days. Shorter is better.

Copy it. GitHub shows it exactly once.

Read this before you use it

A token is a password. Treat it like one.

  • Never commit it into your repo. A token in a file, even a private repo, is a token you should assume is compromised.
  • Never post it publicly. Not in a screenshot, not in a forum, not in a support request.
  • Revoke it the moment you're done with a session. Same screen you created it on. Creating a new one takes thirty seconds.
  • If you think it leaked, revoke first and ask questions after. Revoking costs you nothing.

One more: if you paste a token into a chat and the assistant refuses to use it and tells you to revoke it — that's the correct response, not a malfunction. Revoke it and issue a fresh one when you're ready.

Do this — the commit prompt

Commit these files to my repo using the GitHub API.

Repo: [username]/[repo]
Branch: main

Files:
- [path]: [contents]
- [path]: [contents]

Commit message: [message]

Use the standard sequence: get the HEAD ref, get that commit's
tree, create blobs for each file, build a new tree with base_tree
set, create the commit, then update the ref. All files in one
tree so it's a single commit.

Tell me what you're about to commit before you commit it.

For images or PDFs, add: These are binary — base64 encode them and set encoding to base64 in the blob payload.

Do this — after every session

Revoke the token. Then, if you were working in a terminal, clear your shell history.

Make this reflexive. A token you forgot about is the one that causes the problem.

Roadblock — "It says 404 or not found"

Almost always the token lacking access to that specific repo, not a wrong path. Check the token's repository access.

Roadblock — "It committed but the site didn't update"

Check Vercel's deployment log. A build error means the site keeps serving the last working version — which is the system protecting you. Paste the error to Claude.

Roadblock — "I want to undo a commit"

Don't reverse it — commit a fix forward. Reverting is where people accidentally erase work. Your old versions are all still in the repo either way.

Deliverable

Either a working commit flow with proper token hygiene, or a decision to keep using the web interface. Both are correct.
