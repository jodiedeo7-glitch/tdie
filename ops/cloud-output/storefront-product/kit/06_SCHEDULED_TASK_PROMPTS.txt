IMPORTANT CLAUDE ARCHITECTURE
Current Claude documentation says scheduled tasks run in the cloud, use files saved to your Claude account and can use connected tools. A scheduled task cannot simply be tied to a local computer folder as its normal cloud-state mechanism. Local files/browser/computer access is a separate desktop/local capability. citeturn545658search0turn545658search3

Therefore the default automated architecture is:
Claude scheduled task
-> Claude account/project state
-> connected image provider
-> product data from PRODUCT_SOURCES.md
-> Pin queue
-> Pinterest API only after Standard approval and explicit APPROVE

If Pinterest API is not approved:
- the build still prepares images/copy/queue
- the customer uses native Pinterest publication manually

If Pinterest API is Standard:
- the queue must contain APPROVE state
- a Pin must never be published by the API without explicit customer approval

WEEKLY BUILD
Name: While-You-Sleep: weekly build
Schedule: weekly plus an optional second build day for pace 5 to 7
Working state: Claude account/project files

READ FIRST:
MY_RECIPE.txt
PRODUCT_SOURCES.md
03_THEMED_LOOK_RECIPE.txt
07_PERSONA_PATHS.txt
08_STOREFRONT_PATHS.txt
storefront-log.md
pin-drafts.md
pin-tab.md

JOB
1. Read the persistent state.
2. Resume incomplete work first by stable ID.
3. Select the next ready look.
4. Generate Pin images using the provider/model in MY_RECIPE.txt.
5. Write Pin copy.
6. Create queue records.
7. If PINTEREST METHOD = API STANDARD, set status "ready for approval" and do not publish.
8. If PINTEREST METHOD = NATIVE UI, prepare the customer-facing queue and stop before publication.
9. If a site is configured, prepare/publish the page only through an authorized site connector/path.
10. Log the run.

API RULE
A Pin is publishable only when APPROVE is explicitly present in pin-tab.md or the connected approval UI records the user's explicit approval. A missing approval is HOLD.

PULL/RECOVERY SWEEP
Name: While-You-Sleep: pull and recovery sweep
Schedule: daily at the configured sweep time(s)

JOB
1. Read state without opening a browser unless native UI work is required.
2. Process PULL records.
3. Process incomplete Pin drafts and pages.
4. Process API authorization errors as "waiting: Pinterest authorization".
5. Process image credit errors as "waiting: image provider".
6. Never create a duplicate stable ID.
7. Never publish an API Pin without APPROVE.
8. Log the result.

★ SAVE CREDITS INSTEAD OF TIME?
Skip both tasks. Generate images, write copy and publish Pins manually using the same queue fields.

LEGACY BROWSER AUTOMATION
Not a core task. Do not add a browser-based publisher just because API approval is pending. See 13_PINTEREST_API_APPLICATION.txt.

NO PASSWORDS
Never type passwords or use Pinterest session cookies as an API credential.
