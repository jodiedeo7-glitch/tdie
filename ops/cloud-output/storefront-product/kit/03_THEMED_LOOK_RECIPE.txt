AUTOMATION 1: THE THEMED-LOOK RECIPE

CORE PRINCIPLE
This recipe has two normal ways to execute the same work.

★ TIME-SAVING
Use the automated workflow and approved connectors. Image generation can use OpenArt MCP or Higgsfield MCP when configured. Pinterest API mode requires Standard access and explicit per-Pin APPROVE.

★ CREDIT-SAVING
Do the same steps manually in your image provider and Pinterest. No scheduled task, no API approval requirement.

WHAT ONE LOOK PRODUCES
One look = a coherent group of Amazon products, one destination (Idea List or site page), two original AI-generated styling images, Pin copy, and one logged state record per Pin.

====================================================================
PART 1. RULES THAT NEVER MOVE
====================================================================

R1. No autonomous Amazon browsing. Product discovery, ASIN selection, Special Link creation and Idea List creation are customer actions or eligible approved Amazon API actions. The automated workflow reads PRODUCT_SOURCES.md only.

R2. No Amazon-hosted product image as an AI input unless the customer independently owns/licenses that exact image for AI transformation and commercial use. Clothing is not an exception.

R3. Default AI input is written product attributes. A customer-owned/licensed reference image may be attached only when PRODUCT_SOURCES.md says rights are confirmed.

R4. No invented ASINs, links, destinations or rights status.

R5. Every Pin has the product's required disclosure.

R6. Pinterest API mode uses explicit APPROVE. Native UI mode uses the normal Pinterest composer/scheduler.

R7. Unauthorized browser automation is not the product path. Pinterest Terms prohibit unauthorized automated access. citeturn959482search0

R8. Use public production boards only. A secret board stops scheduling.

R9. Never put prices into Pin copy or generated image text unless the customer explicitly chooses to make a separate non-Amazon price post.

R10. Max 3 image generations per Pin: first attempt plus two correction rounds. If still wrong, hold or drop and log why.

R11. Stable ID = look + pin number + intended publication timestamp. Never create a second Pin with the same stable ID.

R12. Never download marketplace Program Content to create a reusable product library.

R13. For AI-generated or AI-modified images, enable Pinterest's applicable AI label control when the current composer offers it.

R14. Never type a password into Claude.

R15. No private Pinterest endpoints or reconstructed internal requests.

R16. Browser lock is required only for local/manual workflows that actually share a browser. Cloud-only scheduled work should use connector/API tools instead of a local browser.

R17. If a connector or API is not available, use the manual path rather than inventing a browser workaround.

====================================================================
PART 2. READ THE PRODUCT INTAKE
====================================================================

1. Read PRODUCT_SOURCES.md.
2. Select the next row marked ready.
3. Confirm every item has ASIN, written attributes, Special Link and destination URL.
4. Confirm any reference image is rights-confirmed.
5. Log the intake before image generation.

★ SAVE CREDITS INSTEAD OF TIME?
Do product selection, ASIN lookup, Special Link creation and Idea List creation manually in Amazon. Then paste the completed rows into PRODUCT_SOURCES.md. This avoids both API/setup work and any agent access to Amazon.

====================================================================
PART 3. MAKE THE IMAGES
====================================================================

The automated path:
- Use the provider/model in MY_RECIPE.txt.
- Use OpenArt MCP or Higgsfield MCP only if connected and commercially permitted.
- MCP generations use account credits. Website Unlimited is not a connector entitlement. citeturn545658search1

The manual path:
- Open the provider website/app yourself.
- Choose the same provider/model in MY_RECIPE.txt.
- Attach the persona/reference image only when rights are confirmed.
- Generate.
- Save/export the result to your own working folder or upload directly to Pinterest according to the provider's normal export flow.

★ SAVE CREDITS INSTEAD OF TIME?
Generate manually. For a single correction, regenerate only the failed image. Do not regenerate the other Pin.

IMAGE QUALITY GATE
Check:
- exact product count
- product color/shape/detail
- correct person identity when persona path
- realistic hands and fabric
- no logos/marks/text
- correct portrait framing
- readable title overlay when the image contains generated text
- no accidental marketplace screenshot
- no copyrighted/third-party decorative IP

PIN 1
Use the chosen provider/model.
Format A: styled flat lay from written product attributes.
Format B: person-free collage using written attributes.
Never use Amazon-hosted product screenshots as the default source.

PIN 2
Persona path: use the customer's reference image and the chosen provider/model.
No-persona path: use the other person-free format.

====================================================================
PART 4. PINTEREST PUBLICATION
====================================================================

API STANDARD PATH
1. Build the Pin record.
2. Put it in pin-tab.md with status "ready for approval".
3. Customer explicitly marks APPROVE.
4. Only after APPROVE may the configured API publisher create/publish that Pin.
5. Verify publication and log the result.

Pinterest's developer guidelines explicitly say that if an app allows users to schedule Pins, the end user must choose each Pin to be published. citeturn959482search3

NATIVE PINTEREST PATH
1. Open Pinterest's normal composer.
2. Upload the finished image.
3. Add title, description, destination and alt text.
4. Use Pinterest's native scheduling controls.
5. Review the Pin yourself before confirming the publication.

★ SAVE CREDITS INSTEAD OF TIME?
Do all Pinterest publication manually in the native composer. You do not need a developer application.

LEGACY BROWSER AUTOMATION
Do not use this as the normal course path. Pinterest's Terms prohibit unauthorized automated access. See 13_PINTEREST_API_APPLICATION.txt for the founder note and why this is not the recommended route.

====================================================================
PART 5. REVIEW, RECOVERY AND STATE
====================================================================

Before making a new Pin:
- check stable ID
- check pin-drafts.md
- check storefront-log.md
- check for an existing scheduled/published Pin
- use the previous image when still valid
- regenerate only the failed asset

If a run fails:
- preserve completed state
- leave incomplete work marked
- do not create duplicates
- the next successful run resumes incomplete work

If API authentication expires:
- do not attempt browser fallback automatically
- mark the queue "waiting: Pinterest authorization"
- tell the customer to reconnect/re-authorize

If image credits are exhausted:
- mark "waiting: image provider"
- do not silently change plans/models.

If a Special Link breaks or an ASIN is unavailable:
- mark "blocked: product"
- do not invent a replacement link.

====================================================================
PART 6. TIME-SAVING VS CREDIT-SAVING CHECK
====================================================================

At the end of every major operation, use this one-line note only when it changes the user's next action:

★ Prefer to save credits instead of saving time?
Do this step manually instead. Use the exact manual operation described in the matching section.

Do not duplicate every instruction twice when the operation is already obvious.
