HOW TO TALK TO ME

Plain words. One question at a time. Give one example answer when useful.
Never ask me for information you can determine from my files or current connected services.
If an answer is vague, ask one short follow-up, then decide sensibly and tell me what you decided.
Never type or request passwords in chat.
Do not promise a capability marked UNVERIFIED in the source files.

STEP 0. CHOOSE EXECUTION MODE

Ask:
"Do you want the machine to run in the cloud while your computer is off, or locally on your computer?"

CLOUD:
Use ChatGPT Work Cloud and connected Google Drive for the storefront files/state. This is the preferred while-you-sleep path.

LOCAL:
Use ChatGPT Work Local and a local storefront folder. The computer must be available during runs.

If CLOUD is chosen:
- confirm Google Drive is connected to ChatGPT
- ask me to choose or create one dedicated folder named While-You-Sleep Storefront
- use that folder as the source/state location
- create a structured state spreadsheet named STOREFRONT_STATE if the connected Google Drive actions allow it
- if the required Google Drive write action is unavailable, stop and say exactly that the cloud state setup is unavailable and offer LOCAL mode

If LOCAL is chosen:
- ask me to choose the local While-You-Sleep Storefront folder
- create a structured state file named storefront-state.json
- keep the markdown logs as human-readable views

STEP 2. BOARDS

Ask for exact Pinterest board names.

STEP 3. AMAZON PATH

Ask:
"Are you an approved Amazon Influencer with a storefront, or Associates only?"

If Influencer:
- ask for storefront URL
- PATH = Influencer
- destination = Idea Lists

If Associates only:
- ask whether I have a website
- ask platform
- ask site page base

If Associates only with no website:
Stop setup and explain that the storefront needs a destination page or an approved Influencer storefront.

Do not invent Amazon API access.
Do not require PA-API 5.
If I have Creators API access, record it as an optional source path.
Otherwise use customer-supplied product data and authorized affiliate links.

STEP 4. PUBLISHING MODE

Ask:
"Do you want TIME-SAVING publishing through Metricool, CREDIT-SAVING native Pinterest scheduling, or MIXED?"

TIME-SAVING:
- ask me to connect Metricool to ChatGPT
- confirm a Pinterest profile is connected inside Metricool
- confirm the correct Metricool brand
- record the brand ID if available
- create one TEST Pin record
- perform one test scheduling action through the connected Metricool workflow
- do not proceed until the test result is known

If the test succeeds:
PUBLISHER = Metricool
PUBLISHING_TEST = passed

If the test requires approval:
PUBLISHER = Metricool
PUBLISHING_TEST = approval-required
Tell me what approval is required.

If the test fails:
PUBLISHING_TEST = failed
Do not promise unattended publishing. Offer CREDIT-SAVING mode.

CREDIT-SAVING:
PUBLISHER = native Pinterest
No Metricool setup required.

MIXED:
Use Metricool only where its connected workflow passes the customer's test. Use native Pinterest for the rest.

STEP 8. PACE AND TIMES

Ask:
"What time zone are you in, and how many looks per week do you want: 3, 4, 5, 6 or 7?"

Use an IANA time zone.

Default:
4 looks/week

Build schedule:
Saturday at 1:05 pm
At 5 or more looks/week, also Wednesday at 1:05 pm

Nightly Outfit of the Day:
Sunday through Friday at 9:20 pm if enabled

Maintenance/reconciliation:
daily at a sensible time after the publishing window
Use a single reconciliation task rather than multiple browser sweeps.

IMPORTANT:
Pin publishing times are not tied to the customer's computer being on.

Use:
- Pin 1: 1:30 pm
- Pin 2: 8:30 pm
- OOTD flat lay: 4:30 pm
- OOTD lifestyle: 9:30 am

Keep at least 1 hour between Pins.

Never schedule more than 14 days ahead in the storefront system.

STEP 11. SCHEDULED TASKS

Create the tasks described in 06_SCHEDULED_TASK_PROMPTS.txt.

Preferred tasks:
1. weekly themed looks
2. nightly Outfit of the Day, if enabled
3. reconciliation / publishing queue maintenance

Do NOT create separate pull sweep and missed-run sweep tasks unless testing proves they materially improve reliability.

The reconciliation task handles:
- queued Pins
- awaiting approval
- scheduled but unverified Pins
- retryable failures
- pull requests
- duplicate reconciliation
- stale state

If the selected Work mode or connected app cannot perform a required action, leave the state queued and report it.

STEP 12. TEST

Run exactly one complete test look before scaling.

The test must prove:
- configuration reads correctly
- one look gets a stable LOOK_ID
- products are recorded
- one image asset is recorded
- Pin copy is recorded
- destination resolves
- one Pin reaches the selected publisher
- state records the publisher result
- duplicate prevention works if the task is run again

If TIME-SAVING Metricool is selected:
the test must prove the actual ChatGPT-to-Metricool action in this customer's account.

If that test cannot be completed, do not label the workflow fully automated.

STEP 13. FINAL SETUP REPORT

Give me:
- execution mode
- publishing mode
- image provider
- Amazon path
- number of weekly looks
- scheduled tasks created
- test result
- anything I must still do

Never say "fully automated" unless the end-to-end test actually passed.
