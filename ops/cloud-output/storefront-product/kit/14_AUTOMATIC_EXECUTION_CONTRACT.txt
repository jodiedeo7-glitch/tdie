AUTOMATIC EXECUTION CONTRACT

The main product is automatic. Once setup and the account tests pass, the agent chooses the next looks, sources qualifying products, records the buyer's authorized links, creates or updates the per-look destination, makes the paired images, writes copy, schedules through the approved publishing route and reconciles the result. The buyer does not stock a weekly product sheet or create every Idea List.

Credit-saving, manual and mixed routes are optional customer choices. Do not silently convert an automatic setup to one of them when access fails. Preserve the automatic queue and report the exact blocked capability.

CAPABILITY TESTS
Save CAPABILITIES with action, operator, service, account, access method, terms/permission evidence, tested_at, result, readback evidence and whether the scheduled runtime can use it. A connector being installed is not proof of any particular action.
Test product discovery, qualification, authorized link creation/capture, destination create/update and readback separately. Use documented Amazon Creators API where eligible. A supported signed-in browser operator may handle only account actions permitted by the applicable service terms and the customer's authorization. Do not scrape, use hidden endpoints, evade detection, or assume browser permission from a successful page load. Creators API catalog access does not establish Idea List write access.
Choose one operator per external write. Save the handoff packet and returned object ID in the shared state. A second agent must not duplicate a claimed write. Cloud runtime is valid only if every required step is available there. Local browser steps require the computer and application to be available. A mixed runtime needs a tested persistent handoff, not a promise that another tool will eventually do it.

PUBLISHING PERMISSION
AUTOMATIC records the customer's production scope. It does not replace a platform's consent requirements. Record PUBLISHING_PERMISSION_EVIDENCE for the exact publisher and automation arrangement. Pinterest's developer guidelines require the end user to choose each scheduled Pin. Do not treat blanket approval as evidence of an exception. If the proposed unattended route has no documented compatible permission, retain the automatic production queue with error_code publishing_permission_unverified. Review First remains an optional mode; do not relabel it as fully automatic.

SETUP AND ENABLEMENT
Create recurring production tasks PAUSED. Build the first complete look automatically, show the exact test Pin to the buyer, schedule only after its test authorization and read back the schedule. Separately test a controlled scheduled run and reconcile its outputs. Enable ongoing production only after all required capability and permission checks pass. Published and verified require live owning-service evidence; a schedule alone cannot pass the live release gate.

RECONCILIATION
Test board discovery/assignment, scheduled reads, published reads, cancellation and live removal as distinct capabilities. Use supported service UI when no connector action covers a capability and that route is permitted. Missing connector tools do not prove the service lacks the feature. If removal cannot be executed, retain pull_requested and report the blocker. Never mark pulled or verified without readback.

SPENDING
Reserve expected image cost in shared state before submission and account for failed/unknown submissions and retries. Enforce the saved remaining budget in the workflow. A prompt budget is not a provider account spending cap; unrelated provider usage is outside that ledger. No silent upgrades, new permissions or provider/model changes.

RELEASE STATUS
This revision repairs the automatic workflow specification. Full unattended execution remains unverified until the actual account route passes source-to-destination, scheduled execution and live publication tests. Do not advertise a tested cloud Amazon/Idea List capability that has not passed. Do not replace that missing proof with mandatory weekly buyer labor.
