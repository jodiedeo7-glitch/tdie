CUSTOMER EXECUTION POLICY, CANDIDATE REPAIR 4
AUTOMATIC and REVIEW_FIRST are distinct setup choices. All production instructions below use the matching authorization gate. Historical originals are preserved outside this candidate.

During setup, record AUTOMATION_MODE = AUTOMATIC or REVIEW_FIRST in MY_RECIPE.txt and structured state. AUTOMATIC is available only after the customer explicitly authorizes ongoing creation and scheduling within a recorded policy. Record the authorization text, actor, time, permitted accounts, exact board IDs/sections, destination paths, image provider/model, generation budget and period, look pace, channels, schedule/timezone, end date or revocation condition, and customer-supplied sourcing requirement. Do not invent authorization or a budget. If any required field is missing, finish setup before enabling recurring production.

AUTOMATIC: For each eligible look, execute the connected production recipe through publication without requesting ordinary per-image, copy or post approval. Use only complete authorized product rows. Apply every source, rights, image, copy, destination, public-board, cost, timing and duplicate check. After all checks pass, record approval_actor=automation_policy, approval_basis=the saved customer policy ID, policy_version, QA evidence, approved_at and the exact final asset/copy/destination/account/board/section/format/disclosure/timezone/schedule fingerprint. Customer selection fields are used only in REVIEW_FIRST; AUTOMATIC records policy authorization fields instead. Never mark a gate passed merely because the policy exists. Changed output invalidates its old fingerprint: rerun affected QA and policy checks, then record a new fingerprint automatically if still within the authorized policy. A changed account, model, board, destination scope, budget or authorization requires setup authorization again.

REVIEW_FIRST: Keep the original explicit per-Pin customer selection and scheduling authorization. Manual publishing remains customer-controlled. The customer chooses this mode to review every output or conserve connected-service credits.

In AUTOMATIC mode, preflight paid generation against the saved budget and approved model. Record expected and actual charges. Within that authorization, a preflight display is information, not another approval stop. No subscriptions, upgrades, silent model substitution or new account permissions. If an input, budget or capability is unavailable, record the affected item and continue independent eligible work. Only essential login, reauthentication or security verification needs immediate customer action. Never bypass platform approval/security requirements. Missing customer-supplied product intake is a prerequisite failure, not proof of unattended sourcing.

Persist write intent before mutations. Unknown outcome means reconcile provider IDs before retry, never recreate blindly. Resume only missing work. Reconciliation monitors actual publication, not merely scheduling. An initial controlled publisher test may be scheduled under the saved policy after all publication gates pass; read back the schedule before declaring the publisher configured, and independently verify its live publication. A future schedule is not publication.

Customer instructions alone do not establish runtime reliability. Declare unattended production verified only after a separate actual scheduled execution completes the intended connected stages, persists results, resumes safely and produces independently verified live posts. Account availability and external security challenges can still interrupt a run.

REQUIREMENTS

Read this before anything else.

CORE REQUIREMENTS

1. CHATGPT / CLAUDE PATH
The automated storefront path requires ChatGPT Work access. Current OpenAI documentation says Work is available on eligible paid plans and can vary by account, app, region and workspace permissions. Ordinary Scheduled Tasks have broader eligibility than Work, but Scheduled Tasks alone do not turn this kit into the full Work automation.

IMPORTANT PLAN GATE
- TIME-SAVING recurring Work path = requires Work access plus the required connected apps.
- CREDIT-SAVING / MANUAL path = does not require Work.
- A customer may use a lower-cost ChatGPT or Claude plan to prepare copy, product sheets and image prompts, then run the image provider and Pinterest steps directly.
- Do not tell a customer that ordinary Scheduled Tasks alone provide the full storefront automation.

Work Cloud is preferred for the true while-you-sleep path. Work Local is the fallback when the workflow requires a local folder or local browser session. If Work is unavailable, continue with the CREDIT-SAVING / MANUAL path instead of stopping setup.

2. AMAZON
You need an approved Amazon Associates account.

If you want the Amazon Influencer Idea List path, you also need Amazon Influencer approval and a storefront.

Amazon's PA-API 5 is deprecated. Amazon's current successor is Creators API. Do not assume you have Creators API access. The customer workflow may use customer-supplied Amazon product data and authorized affiliate links instead.

3. PINTEREST
You need a Pinterest business account with public boards.

Pinterest's native scheduler supports standard Pins up to 30 days ahead and up to 10 future Pins at a time.

4. IMAGE PROVIDER
Higgsfield is the preferred connected image provider when the customer selects that path. Higgsfield officially supports ChatGPT integration, and its connector requires an active paid Higgsfield subscription.

CREDIT-SAVING / MANUAL alternative:
The customer may run the selected image provider directly instead of through a connected action. ChatGPT or Claude can prepare the prompt and QA checklist, then the customer returns the finished asset for review. If the customer uses customer-owned or properly licensed imagery instead of generated imagery, record that source and its rights.

In every path, record the exact provider, model/plan when applicable, and commercial-use rights in MY_RECIPE.txt. Never silently spend credits or switch providers.

5. METRICOOL
Only required for TIME-SAVING publishing.

Metricool's MCP can connect to ChatGPT and can create, schedule, publish and update posts on connected networks within the customer's Metricool plan limits.

Metricool Free has a 20-published-post monthly limit. The storefront does not assume a particular Metricool tier. Customers who exceed the Free limit need a paid plan.

6. GOOGLE DRIVE
Required for the preferred CLOUD state/asset path when the workflow uses Google Drive.

ChatGPT can connect to Google Drive and, where the required permissions/actions are enabled, read and update supported Drive-family files.

7. THE BRAND CLOSET™
Only required for the optional Outfit of the Day automation.

WHAT THE CUSTOMER DOES NOT NEED

No separate desktop-browser automation subscription is required by this storefront kit.
No Pinterest API developer application is required for the normal customer path.
No Amazon PA-API 5 integration is required.
No website is required on the Amazon Influencer path.
No Instagram is required for the core storefront.

COST-SAVING PATH

Choose CREDIT-SAVING if you want to reduce automation subscriptions or connected-tool usage.

Use a lower-cost ChatGPT or Claude plan for the planning, copy and image-prompt steps you want help with.
Run image generation directly in your selected provider when that is cheaper than connected execution.
You perform the final Pinterest scheduling step.

Choose MANUAL if you want to minimize automation further. Use the recipes as checklists, perform each build step directly, and maintain the state/log yourself. No Work task or Metricool subscription is required.

TIME-SAVING PATH

Choose TIME-SAVING to use a tested connected Metricool publishing path. Choose AUTOMATIC or REVIEW_FIRST separately during setup: Automatic applies saved authorization; Review First requires exact per-Pin approval.

IMPORTANT VERIFICATION GATE

Publishing always requires recorded authorization and passing QA. AUTOMATIC uses the setup policy; REVIEW_FIRST uses exact customer approval. The initial controlled publisher test follows that same gate. A successful schedule readback proves scheduling only, not future unattended execution or live publication.

If exact board assignment, mode-specific authorization or publisher readback is unsupported, mark the affected path blocked or manual. Do not claim end-to-end verification.

COMPUTER REQUIREMENT

CLOUD mode: computer can be off during the run.
LOCAL mode: computer must be available for local work.

Never type passwords into a task prompt. Complete sign-in through the provider's own sign-in flow.
