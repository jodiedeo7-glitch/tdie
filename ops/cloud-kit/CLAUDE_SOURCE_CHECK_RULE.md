# MANDATORY SOURCE CHECK — before and after every task

Added 25 Sep 2026, founder instruction, after repeated failures to read live project files before writing content.

Before doing any task: name which live files it touches (voice, pricing, canon, SOP, whatever applies), actually open and read those exact files with the tools, then start the response with "Sources checked: [file names]." If the specific files can't be named, stop and go check before writing anything — never work from memory or a past session's summary of a file.

After finishing any task: re-read what was produced against those same files and confirm "This matches [file names]" or name the specific line that doesn't.

If a response doesn't start with "Sources checked: [files]," that's proof the step was skipped. Stop before reading further, say so, and require it to be redone with the sources actually checked first — not apologized for and continued.

## Task completion reporting

Added 26 Sep 2026, founder instruction, given directly in chat. Applies to every scheduled task and every requested task alike — not just Threads, not just one job.

**If every check in the task's own instructions passed and nothing needs Jodie:** the report is one line — "Task completed successfully" or the plain equivalent, with one factual anchor if the task has an obvious one (a queue count, a total). No recap of steps, no bullet list of what was checked, no bold headers, no restated numbers otherwise.

**Notes are must-know only.** Something failed. Something looks wrong or off from what's expected. A number that doesn't match. A call the task made on Jodie's behalf that she'd want to know about. Nothing else earns a line — this is what "keep notes to a must-know requirement" means in practice.

**This does not shrink an actual deliverable.** A task whose whole job is handing Jodie data or analysis — the Friday numbers, a DFY calendar build's research findings, an audit table — still reports that in full. What gets short is the wrapper around it: whether the task ran, whether the checks passed. If the task also has something for her to act on (a draft to review, a decision to make), lead with that one thing before the details.

**Mid-task decisions:** if one option is clearly better, make it and keep going. Don't surface it as a question unless it's a genuine toss-up with no clearly better side.

**When a task truly cannot finish without Jodie:** say so plainly, as exactly one of — a direct question, the exact text to paste somewhere, or the exact numbered steps to take. Never a vague "let me know if..." and never (see above) "open a new chat and tell Claude ___."
